# Project Memory

## Git Workflow

- Never include `codex` (case-insensitive) or Codex attribution in branch names or pull request titles. Use task-specific, product-oriented names instead.
- Work directly on `main`; do not create branches or pull requests unless the user explicitly requests them.

## Visual Fidelity

- Do not describe the KiCad fixture preview as perfect or complete. Treat it as a narrow research renderer and state its supported primitives.
- Preserve KiCad's board-coordinate rotation convention when transforming footprint-local pad coordinates. Validate transformed pads against connected track endpoints, not only aggregate counts.
- In placed `.kicad_pcb` footprints, transform pad `at` x/y from footprint-local coordinates, but treat the pad `at` angle as the serialized board orientation. Do not add the footprint rotation again. Validate the long axis of signal and mounting pads against the source footprint and connected traces.
- Render the declared pad and drill shapes and dimensions. In particular, through-hole `oval` pads with `drill oval` must appear as pill-shaped copper with a pill-shaped hole, not as rectangles with circular holes.
- A board preview is not visually representative if it omits filled copper zones or source drawing layers. Render serialized `filled_polygon` geometry and expose footprint silk, fabrication, courtyard, drawing, and comment layers separately.

## Interaction Validation

- For Vite-served JSON modules, do not add native JSON import attributes to dynamic imports. Vite transforms JSON into JavaScript modules, so `{ with: { type: "json" } }` makes the browser reject the transformed `text/javascript` response even though build-time checks pass. Verify dynamic chunks through the live development server.
- The application and UI must remain protocol-, component-, feature-, and project-agnostic just like the engine. Demo/test-specific UI code must be minimal and isolated to fixture loading or clearly bounded development surfaces; it must not add bespoke panels, conditionals, layout rules, labels, controls, or interaction behavior to the general product implementation.
- Do not let the graph UI appear to accept an electrically invalid connection and rely only on the Diagnostics tab to explain it later. Validate endpoint and contract compatibility before committing an edge, or make rejection immediate and visible at the interaction site.
- Keep generic pin-pool and function-level capability matching as test-local semantics, not as a shipped fake FPGA component. Real FPGA support must begin with an identified part definition; an external transmitter remains a separate provider topology.
- When changing repeated JSX controls, patch with component-specific context and inspect the exact occurrence. The provider mode grid may collapse to one column for a single generic mode, while the I2C auto/manual grid must remain two columns.
- Provider inspector editability and mode-switch binding retention must come from the selected ProviderModeDefinition signal map. A `pinSelector` mapping is user-editable and preserves authored provider bindings; a fixed `pin` mapping is read-only and discards conflicting authored provider bindings.
- Render active provider requirements as metadata-labeled, individually connectable target sockets on the component node. When those sockets exist, omit the anonymous target handle so users cannot bypass exact requirement selection.

## Roadmap Direction

- Treat the current Pico RetroDigital main board as the product north star, while keeping the smaller RP2350 plus IT66121 board as an EDA capability MVP.
- After shared resolver and document foundations, advance two cooperating tracks: full semantic-graph representation of the north-star design and the editor/PCB path through placement, manual routing, zones, and KiCad export. Validate them through subsystem slices and integration gates rather than completing either track only against toy data.
- Keep schematics as a generated read-only inspection and debugging view for now. Prioritize semantic graph authoring and PCB capabilities; do not invest in manual schematic editing unless later user demand or export requirements make it necessary.
- The checked-in north-star video topology is browser-reviewable at `/north-star.html`. It intentionally has no authored board yet; the PCB tab must show a generic empty state until qualified board and footprint geometry is captured. Do not add a fake board merely to make the tab render.
- A fixed fixture catalog is scoped to its initial project dependencies. Disable project replacement controls on that surface unless catalog recomposition becomes atomic with source replacement, otherwise dependency-only definitions and provenance labels become stale.
- Pin a dirty hardware reference by exact working-tree file hashes, not Git HEAD alone. Keep semantic design inputs, broader stale/capture evidence, and normalized electrical connectivity as separate deterministic aggregates.
- A reference with no explicit license, current DRC/ERC, fabrication linkage, or hardware-test evidence is `NOASSERTION`, non-golden, and unqualified even if source and production artifacts exist. Stale reports must say they do not apply to the pinned design.
- Preserve schematic UUID, footprint UUID, and pad UUID as separate identity levels. Keep 1:N and display-reference anomalies explicit, use pad UUID for net membership, and require one subsystem owner plus closed package/contract/power status for every normalized object.
- Source-free reference verification must read no external project path and must not claim to re-prove extraction. Validate repository-local hashes, canonical order, internal closure, constraints, and deliberate mutations; record omitted schematic-wire or power-symbol membership as first-class remaining work.
- The G1 schematic capture uses KiCad's canonical netlist for named physical-pin membership and embedded library geometry for wire, label, junction, power-symbol, and no-connect evidence. In KiCad screen coordinates, rotate library pins first, then apply placed-symbol mirror: mirror x flips the resulting y coordinate and mirror y flips the resulting x coordinate.
- The normalized north-star schematic and PCB have exact logical connectivity for all 337 represented physical pins. Keep 22 blank/mounting/thermal pads as exact non-electrical exclusions, J5 A8/B8 as one fingerprinted SBU waiver, and duplicate C5 as a separately validated physical-identity issue.

## Resolver Determinism

- Store component, contract, and function definitions in a proper external library/catalog boundary and load them dynamically. Do not keep production definitions embedded in the engine or UI. Use only real, identified components in product/demo data, not generic or fake stand-ins such as `GENERIC_FPGA`.
- Treat TE Connectivity 1-1734839-4 as the north-star 14-position video FFC connector, not an HDMI receptacle. RP2350A is QFN-60 and RP2354B is QFN-80; derive these device packages from component descriptors instead of hardcoding them in UI fixtures.
- Demo and test fixtures may be protocol-, feature-, component-, or project-specific data. The engine itself, including resolver, allocation, topology interpretation, projection, layout, hit testing, and rendering, must not know any specific protocol, feature, or north-star identity. Keep component/package/contract mappings in definition data and project-specific wiring in authored fixture bindings; executable engine functions remain general interpreters of that data.
- Do not pre-reserve bindings from every `intent.provides` edge. Protect hard provider pins only for validated, unambiguous function topology with valid endpoints, modes, signal maps, and overrides. Include fixed mode pins, diagnose collisions between valid provider claims, and let orphan, invalid, or ambiguous provider edges claim nothing.
- Duplicate edge IDs must invalidate every occurrence rather than selecting a source-order survivor. Canonicalize hard reservation ownership, report conflicts, and test full `ResolvedProject` equality across all source edge-array permutations.
- Inline topology must be function/package data-driven. For a series interposer, replace the selected logical net with stable provider and connector segments around a generated component, keep authored endpoint bindings unchanged, and project the generated component so neither ratsnest segment disappears.
- The Pico RetroDigital north-star video output is RP2354B U3 driving the TE 1-1734839-4 FFC through eight 220 ohm series parts. It contains no IT66121 or HDMI receptacle. The exact GPIO12..19 order is CLK-, CLK+, D0-, D0+, D1-, D1+, D2-, D2+, with GPIO8/9 for DDC and GPIO10 for CEC. J3 pin 2 is only a candidate HPD node and remains unverified.
- Do not treat the current TE FFC semantic signal map as intrinsic, verified physical-pin identity. Exact north-star parity still needs qualified passive/diode identities, independently verified physical-pin metadata, differential-pair constraints, general exposure bindings for remaining circuitry, and broader video support circuitry. Until then, label the pinned video fixture as a non-golden physical-topology slice, not an exact subsystem recreation.
- Preserve one resolved identity for an authored multi-endpoint physical net. Canonicalize endpoint arrays, reserve its component pins before semantic allocation, invalidate every authored net in a same-pin conflict, and derive only view-level N-1 ratsnest segments from that shared net. When a physical net realizes semantic intent, link it explicitly by stable source-map identity (`edge`, `signal`, and optional topology `feature`/`segment`). Allow only compatible shared pin claims, replace the semantic net with the authored identity, remap generated references, and diagnose incompatible or ambiguous ownership instead of duplicating connectivity. Unlinked overlaps remain hard reservations. Bind captured authored substitutes for generated components on the owning semantic edge by generated source-map identity, authored node, and generated-terminal-to-authored-pin mapping; substitute endpoints before authored segment reconciliation. Suppress the duplicate generated component only when it has resolved terminal endpoints that can actually be substituted.
- Unqualified north-star passives and support parts belong in a content-pinned, reference-derived captured-instance package. Keep fixture-only packages under `fixtures/definition-packages/`, outside the protected source-free north-star reference closure. Do not weaken production manufacturer/part-number requirements or expose captured instances in normal production palettes.
- Object-valued include fields use their declared defaults when the include object is absent. Off must preserve the original net and dependency state; invalid selectors and multiple active interposers must diagnose rather than silently no-op or implicitly chain.
- Before an inline rule creates authoritative net endpoints, validate that its generated component exists and that the provider/connector terminals both exist and are distinct. Invalid package data leaves the logical net unsplit.

## Project Documents

- Omit absent optional fields when constructing project nodes, edges, and patches. Never author properties with `undefined`; `ProjectDocument` correctly rejects them as `PROJECT_JSON_LOSSY` because JSON cannot preserve the distinction.
- Public document patches target stable node/edge IDs. Array indices belong only to generated inverse operations used to restore exact ordering.
- Keep `getSnapshot()` frozen and identity-stable until a real document change so external-store consumers are safe. Reject no-ops without history changes, make batches atomic, deep-clone exposed records/copies, and restore absent optional containers exactly during undo.
- Validate JSON-only data at source and patch ingress without reconstructing known fields, so unknown future keys survive save/load while undefined, non-finite and negative-zero numbers, BigInt, functions, symbols, cycles, sparse/noncanonical arrays, accessors, and hidden data are rejected.
- In React, own one `ProjectDocument` and subscribe with `useSyncExternalStore`; do not mirror `ProjectSource` in component state. Keep graph positions and selection ephemeral, retain positions through undo/redo, and reset them only when replacing the document.
- Capture the document revision alongside resolver output, delayed connection options, and the start of asynchronous file reads. Apply those results with `expectedRevision` so they cannot overwrite intervening edits; load errors must leave the current document unchanged.
- Treat a mixed React Flow deletion as one gesture and one atomic batch. Use the unified `onDelete` payload, and omit explicit edge-removal patches for root or nested-binding edges that `removeNode` will already cascade.
